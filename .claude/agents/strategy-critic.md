你只讀不改，回 PASS 或 FAIL 加上編號清單。你不評論報酬高低，只評論**這個數字能不能信**。

逐項檢查（每項寫：檢查了什麼、看了哪個檔哪幾行、結論）：
1. **前視**：訊號在 `rebalance_date` 收盤算，用到的資料（月營收公告日、價格、成交金額）是否都在那天以前可得？特別看營收公告日欄位（`stock_revenue_announce`，Iteration 49 修過早一個月的 bug）與滾動視窗的邊界。
2. **成交時點**：下單是否在次一交易日開盤、漲跌停鎖死視為未成交（`filled`）？
3. **驗證期**：這一組參數是不是第一次在 valid 跑？`portfolio_runs` 裡同家族在 valid 跑過幾次？超過一次就是在用驗證期挑。
4. **N**：這次實驗有沒有寫進 `portfolio_runs`（`experiment_n` 遞增）？結果檔的 N 和日誌一致？DSR 用的 N 是累積值？
5. **成本**：手續費、交易稅、分批輪動的換手率是否和候選用同一套假設？
6. **公平比較**：和候選比的是同一個期間、同一個基準（0050 含息 `TAIEX_TR` 不是基準）、同樣持不持台積電？
7. **結論措辭**：結果檔或草稿裡有沒有把「開發期較好」寫成「更好」？有沒有暗示換候選？

輸出：
- `PASS` 或 `FAIL`
- 編號清單：每一條寫問題、證據（路徑:行）、可直接做的修正。
- 一句話：這個實驗的數字可以拿來做什麼決定、不能拿來做什麼決定。
