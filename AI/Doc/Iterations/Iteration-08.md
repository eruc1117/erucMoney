# Iteration 8 — M2 新聞模型（XGBoost）訓練管線與整合

**日期：** 2026-08-06

## 目標（request.md 模型二規格）

模型二規格為「FinBERT + XGBoost 時序滯後影響模型」，現況為關鍵字規則引擎。
本迭代建立完整 XGBoost 訓練管線與推論整合；情緒提取暫用既有關鍵字法
（FinBERT 需下載大型模型，列為未來升級）。

## 實作內容

### 1. 訓練管線 `XGBoost/train_m2.py`

| 項目 | 設計 |
|------|------|
| 樣本單位 | 新聞日 × 追蹤股票 |
| 特徵（7 個） | avg_sentiment_24h / 72h（時間衰減）、news_volume_gap、keyword_hit、stock_news_count、price_return_t1、sector_sentiment |
| 標籤 | 新聞日後 3 個交易日累積報酬 >+1.5% Buy / <-1.5% Sell / Hold |
| 驗證 | 依新聞日期時序切分 80/20 |
| **資料充足性門檻** | 樣本 < 300 → 只出報告、**不部署模型檔**，避免用垃圾模型取代堪用的規則引擎 |

### 2. 推論整合 `model2_news.py`

- `_load_xgb()` lazy-load `XGBoost/saved_models/m2_news_xgb.joblib`（**檔案不存在即維持規則引擎**，零風險部署）
- `_xgb_signal()` 以與訓練一致的 7 特徵推論，任何失敗 fallback 規則
- 已煙霧測試：模型缺檔時走規則路徑正常

### 3. 訓練資料現況（誠實揭露）

```
新聞 121 則，僅覆蓋 3 個日期（2026-03-16、03-22、08-06）
可用樣本 44 筆 < 門檻 300 → ⛔ 模型未部署
```

**資料累積雙軌進行：**
1. 每小時排程新聞爬蟲（Iteration 4）——向前累積
2. Common Crawl 歷史回補（背景執行中，2025-09 ~ 2026-02 共 6 個月）——向後回補
   - 注意：CC 爬蟲每則有 60~300 秒禮貌性等待（反封鎖設計），全量需長時間背景運行
   - 每完成一個月即入庫，中斷可續跑

樣本達標後重跑 `python train_m2.py` 即自動訓練並部署，服務重啟後生效。

## 本迭代對「22 檔全 Buy」問題的意義

Iteration 7 觀察到 M2 規則引擎的產業級信號可單獨翻轉全部最終決策。
XGBoost 模型將以「該信號歷史上是否真的帶來超額報酬」為學習目標，
且特徵含 `stock_news_count`（個股相關新聞數），具備個股區分能力——
這正是規則引擎缺少的。模型部署後此問題可望緩解。
