# Iteration 18 — adj_close 根本解 + 減資：發現比除權息更嚴重的汙染源

**日期：** 2026-08-07

## 起點

Iteration 17 留下兩個問題：

1. `stock_daily_prices` 仍存未調整價格，靠 `dividend_adj` 在讀取端修正——
   任何直接查該表算報酬的程式碼都會踩坑
2. 未處理減資

本迭代兩個一起做。結果發現**減資的破壞力遠超除權息**。

## 一、減資：單日 +123% 的假漲幅

`TaiwanStockCapitalReductionReferencePrice` 回補 24 檔，得到 **11 筆減資**（7 檔）。
數量遠少於除權息的 479 筆，但幅度驚人：

| 股票 | 日期 | 原始「報酬」 | 還原後 |
|------|------|-------------|--------|
| 2337 旺宏 | 2017-08-28 | **+123.56%** | +9.99% |
| 2388 威盛 | 2012-10-04 | +86.45% | −6.78% |
| 6116 彩晶 | 2012-09-27 | +86.39% | −6.81% |
| 2323 中環 | 2015-09-17 | +26.24% | +4.40% |

注意方向與除權息**相反**：除權息參考價低於前收（配息發出去），
減資參考價高於前收（股份被註銷）。

一筆 +123% 的假報酬落在 20 日滾動窗內，足以把該股的波動度估計推高數倍——
而先前所有版本的模型都在學這些數字。

## 二、adj_close：把調整做進欄位裡

新增 `stock_daily_prices.adj_close`（migration 005），與 `us_daily_prices.adj_close` 一致。

**回溯還原演算法**（`Crawler/rebuild_adj_close.py`）：

```
每個公司行動：factor = 參考價 ÷ 事件前收盤
adj_close[t] = close[t] × ∏(factor for every event with ex_date > t)
```

把事件**之前**的歷史價格按比例縮放，使跨越事件的報酬率連續。
最新一段的累積 factor 為 1，故 `adj_close` 最新值等於 `close`，方便對帳。

安全機制：factor 落在 (0.2, 5.0) 之外視為資料異常，記錄警告並略過，
避免單筆壞資料把整段歷史價格扭曲。

回補結果：**167,005 筆 adj_close**（114 筆缺值正是既有的零價格列，正確排除）。
2330 的調整係數：2003 年 0.3322 → 2010 年 0.6118 → 2020 年 0.8807 → 今日 1.0000。

### 驗證：缺口確實消失

| | 原始報酬 | 還原後 |
|---|---------|--------|
| 公司行動日 平均 | **−3.465%** | +0.463% |
| 公司行動日 標準差 | **9.429%** | 3.003% |
| 一般交易日 平均 | +0.057% | +0.057%（不變） |
| 一般交易日 標準差 | 2.716% | 2.715%（不變） |

行動日的系統性偏差消失、標準差降低 68%，而**一般交易日完全不受影響**——
這正是正確調整該有的樣子。

## 三、模型改善（三個版本對照）

| | 原始 | Iter 17（僅除權息） | **本迭代（adj_close 含減資）** |
|---|------|-------------------|---------------------------|
| 波動率 相關係數 | 0.566 | 0.571 | **0.610** |
| 波動率 R²(log) | +0.473 | +0.483 | **+0.485** |
| 波動率 QLIKE | −6.4799 | −6.4974 | **−6.5376** |
| 跳空 相關係數 | 0.5767 | 0.5705 | **0.5874** |
| 跳空 R² | +0.2924 | +0.2934 | **+0.3385** |
| 跳空 MAE | 0.6647% | 0.6550% | **0.6424%** |

跳空模型 R² 相對原始版本提升 **16%**，波動率相關係數提升 **7.8%**。
**改善幅度明顯大於僅處理除權息時**——證實減資才是主要汙染源，
儘管它的事件數只有除權息的 2.3%。

## 四、消費端全面改用 adj_close

| 檔案 | 變更 |
|------|------|
| `UnifiedModel/features.py` | `LOAD_SQL` 加入 `adj_close`；報酬、均線、RSI、MACD、布林全部改用它 |
| `UnifiedModel/train_gap.py` | `TW_SQL` 加入 `adj_close`；個股報酬改用它 |
| `UnifiedModel/dividend_adj.py` | 面板含 `adj_close` 時直接使用（更完整，涵蓋減資）；否則退回原查表法 |

一律以 `COALESCE(adj_close, close_price)` 讀取，舊資料缺值時自動退回原始收盤，
不會因為欄位是 NULL 而讓整個管線失效。

## 五、修掉一個我自己寫錯的量測

`test_dividend_impact.py` 原本用「調整前後報酬有差異的天數」來數事件，
改用 adj_close 後這個數字變成 **91,572**（離譜）。

原因：adj_close 會把事件**之前**的整段歷史都按比例縮放，
所以「有差異的日子」等於「最後一次公司行動之前的所有日子」，而非事件本身。
已改為直接查公司行動表的日期。修正後：485 筆事件、受汙染 9,700 筆（5.81%）。

這類「量測方式隨實作改變而失效」的問題很隱蔽——
數字沒有報錯，只是默默變成另一個意思。

## 誠實評估

本迭代的改善是**三次迭代裡最大的一次**，而關鍵不在演算法而在資料完整性：

- Iteration 17 只處理除權息 → 波動率相關 0.566 → 0.571（+0.9%）
- Iteration 18 加上減資 → 0.571 → 0.610（+6.8%）

**11 筆減資的影響大於 479 筆除權息**，因為幅度差了一個數量級。
這再次印證 Iteration 17 的教訓：處理離群值時，要看的是「幅度 × 擴散範圍」，
而不是事件數量。

## 遺留問題

1. **除權息資料最早僅到 2003-06、減資資料的涵蓋範圍未逐一驗證**。
   1992~2003 的公司行動仍未還原，該期間的 adj_close 與真實還原值有落差。
2. **LSTM 與 M3 籌碼模型尚未改用 adj_close**。
   `LSTM/data_loader.py` 與 `Crawler/m3_features.py` 仍讀 `close_price`。
   兩者的結論（LSTM 等同天真基準、M3 買進訊號 56.87%）可能因此需要重新檢驗。
3. **前端 K 線圖仍顯示原始 close**。這是正確的（顯示應用實際成交價），
   但除權息日的跳空對使用者可能造成困惑，可考慮加註標記。
4. **未處理股票分割**。台股較少見，但 FinMind 若有對應 dataset 應一併納入。
