# Iteration 50 — 打敗大盤：44 次實驗的網格搜尋，候選是「公告窗口反應＋動能、分三批、固定持有台積電」

**日期：** 2026-10-09
**依據：** 使用者：「再試，以不同組合及更換頻率，或是其他條件，不停自我優化，直到超越」。
**規則（沒有破）：** 只在開發期（2018-01~2021-12）搜尋；候選到驗證期（2022-01~2024-09）用同一組參數確認；每一次回測都寫進 `portfolio_runs`、N 加 1、失敗的也算；
DSR 用累積的 N 與各版本月 Sharpe 的變異數算；**保留期（2024-10 起）沒有打開**。

## 一、做了什麼

### 引擎多了五個旋鈕（`portfolio_signal.py`、`portfolio_backtest.py`、`portfolio_search.py`）

| 旋鈕 | 內容 |
|---|---|
| 分批輪動 `--tranches K` | 每月只換 1/K：到期那一批賣掉、補 K 分之一檔新的，其餘不看排名照留。年換手從 13~20 倍壓到 2~4 倍 |
| 緩衝區 `--buffer` | 月月重排但上期持股在前 N 名就不賣（放到 100、150） |
| 訊號 `mom`、`win3`、組合 `a+b` | 12-1 動能（跳過最近一個月）、最近三個公告窗口的累積異常報酬；`+` 是候選池內百分位排名平均，每個成分都要有值 |
| 權重 `--weighting liq` | 按 60 日成交金額比例、單檔上限 10% |
| 台積電 `--tsmc-weight est` | 沒有 0050 持股權重表，用滾動迴歸估：0050 日報酬對「台積電」與「流動性前 100 等權」做 OLS，台積電係數夾在 [0.2, 0.7]，只用訊號日以前 250 個交易日（最少 120 天，不足用 0.35）。估出來 2018-19 約 0.38、2020 0.46、2021 0.54、2024-26 0.55 上下，與公開資訊走勢一致 |

`portfolio_search.py --round {turnover,universe,combo,tsmc} --segment dev|valid`：一批設定依序跑、每個都正式寫日誌、印總表。測試 `test_portfolio.py` 20 項（分批只換到期批、組合排名平均、權重上限、分批壓低換手、台積電權重估計能還原 0.5 的合成混合）。

## 二、讀法：「超越了」但「還不能說不是運氣」

1. 扣成本後打敗 0050 的設定找到了，而且開發期找到、驗證期加碼確認、七年六正，三個硬門檻過了兩個（主動報酬、IR、換手）。
2. **DSR 0.13 不是裝飾**：44 次嘗試後，月 Sharpe 0.16（年化 IR 0.56）這種程度，純靠運氣在 44 個版本裡挑最好的也挑得到（SR* 月 0.34）。
   要讓 DSR 過 0.95，不是再搜參數（N 會更大），而是**用沒碰過的資料**：保留期 2024-10~2026-09（24 個月）只能開一次，加上從現在起的紙上交易。
3. 真正的轉折是「持台積電」，不是訊號；訊號裡動能貢獻比公告反應大（mom-t6 單獨就 +7.6%／+9.8%）。這和計畫原本的假設（月營收公告反應是主訊號）不同，誠實記下。
4. 相鄰設定 ±5% 的雜訊說明：任何「最佳參數」都別信到小數點，分三批、150 或 300 檔、t3 或 t6 之間的差異不值得再搜。

## 三、沒做的與下一步

- **不要再搜開發期**（每搜一次 N 加 1、SR* 更高）。下一步照計畫：候選進紙上交易（階段 4，每月 11 日自動出清單、模擬帳戶記帳），3 個月後與保留期一起做最後一次判定。
- 保留期什麼時候開：等紙上交易跑滿 3 個月、或使用者決定；`--segment holdout --holdout-once`。
- 台積電權重改用真的 0050 持股權重（元大每日 PCF）替換估計值；估計值與實際差多少要記。
- 用對齊後的 `stock_revenue_announce` 重跑第 39 次迭代的事件研究（Iteration 49 的 bug）。
