# Iteration 31 — 統一模型目錄、新增成交量模型、每頁可選模型

**日期：** 2026-08-09

## 需求

> 目前所有模型都應該要在所有分頁頁簽中使用，資料來源都相同（包含其他國家資料、夜盤），
> 依照模型本身需要的資料進行訓練。在閒置資金跟投票決策，可以選擇使用那些模型。
> 依照目前有的資料重新評估可以新增那些模型。並使用到每一個分頁頁簽。

## 先講清楚改之前的狀況

「有哪些模型」這件事散在四個地方各說各話：

| 位置 | 內容 |
|------|------|
| `Prediction.jsx` 的 `MODELS` 常數 | 10 個 LSTM |
| `roles.py` 的 `ROLES` | 7 個角色，其中只有 1 個 LSTM |
| `cash_allocator.py` 的 import | gap／range／risk／m3 |
| `model_registry.MODEL_TYPES` | 版本管理用的另一份清單 |

實際後果是：**「預測比對」頁密集監控 10 個已證實沒有 edge 的 LSTM，
而真正在做買賣決策的四個模型完全不在那一頁上**；閒置資金一個 LSTM 都沒用到，
投票也只有 `m02_stacked` 一個（`voting_engine.py:54` 寫死）。

## 一、統一資料層 `UnifiedModel/panel.py`

在此之前每個 `train_*.py` 各寫一份 `load_data()`，各自決定接不接夜盤。
Iteration 30 要把夜盤加進振幅與波動率時，得分別改兩支檔案再分別驗推論端——
而 `risk_model` 就曾因欄位對不上**靜默退回 EWMA**，線上完全看不出來。

現在改成宣告式：

```python
panel.build(blocks=['price','chip','cs','market','night','futures'])
```

| 區塊 | 來源 | 特徵數 | 起始 |
|------|------|-------|------|
| price | stock_daily_prices | 24 | 1992 |
| chip | stock_chip_analysis | 17 | 2012 |
| cs | 同日橫斷面 | 7 | 2012 |
| market | 同日全體聚合 | 5 | 2012 |
| us | us_daily_prices（12 檔） | 17 | 2001 |
| night | futures_daily 夜盤 | 8 | 2018 |
| **futures** | **futures_daily 未平倉＋大小台** | **9** | **2018** |
| intl | index_daily_prices（KOSPI／Nikkei） | 7 | 2015 |

**加區塊會砍樣本，而且砍得很兇**——`build()` 一律把代價印出來：

```
price+chip+cs+market                 165,789 列  1992-03 ~ 2026-08
price+chip+cs+market+us              142,188 列  2001-08 ~ 2026-08
price+chip+cs+market+night            49,936 列  2018-01 ~ 2026-08
price+chip+cs+market+night+futures    44,431 列  2018-02 ~ 2026-08
全部八個區塊                           40,364 列  2018-02 ~ 2026-08
```

### `align()` 為什麼不只是 dropna

因為 **dropna 抓不到被捏造的值**。`features.build_stock_features` 對三大法人欄位
做了 `fillna(0.0)`，所以 2012-05（籌碼資料起點）之前的每一列都有「買賣超為零」
的籌碼特徵，看起來完整、實際上是憑空的。

本次評估第一版就吃到這個坑：樣本從 1992 起算 165,664 列，前 20 年的籌碼特徵全是假的。
`align()` 因此除了 dropna 還套用日期下限。**這個修正直接翻轉了一個模型的結論**（見第三節）。

## 二、新資料源：期貨未平倉與大小台結構

`futures_daily` 有兩塊從來沒被任何模型用過的資料：

- **open_interest** — 期貨版的籌碼面。價漲而 OI 增＝新多單進場；價漲而 OI 減＝空單回補。
  同樣的漲幅，兩種含意完全不同。
- **MTX（小台）** — 單口是大台的 1/4，是散戶的主要工具。小台/大台成交比是散戶參與度的代理。

兩個實作上的坑：

1. **夜盤沒有 OI。** `after_market` 的 open_interest **2,095 筆全部是 0**——
   OI 是日盤收盤後才公布的日結數字。所以整表落後一日，掛在 D 日的值只用到 D−1 以前。
2. **換月會讓 OI 歸零重來。** 近月每月第三個週三結算，跨契約的變動率毫無意義
   （實測有 **+557%** 的假跳動）。改成契約內比較，並把「進入本契約第幾天」當成特徵。

## 三、新模型評估：三個候選，一個通過

選題依據寫在 `explore_new_models.py` 檔頭：這份資料已反覆證實**方向沒有 edge、
量級與排序有**，所以候選一律不做第四個方向預測器。

| 候選 | 用途 | 排序相關 | 天真基準 | 差距 | 最差折 | 判定 |
|------|------|---------|---------|------|--------|------|
| **成交量** | 進場前的流動性檢查 | **+0.4639** | +0.3588 | **+0.1051** | +0.0908 | **新增** |
| 下檔風險 | 非對稱停損距離 | +0.2570 | +0.2506 | +0.0064 | −0.0064 | 不新增 |
| 相對強弱 | 選股排序 | +0.0384 | +0.0164 | +0.0220 | +0.0078 | 不新增 |

三個天真基準都刻意選了難打的：

- 成交量 → **量能持續**（未來 5 日均量 ≈ 最近 5 日均量）。第一版用常數 1.0，
  那等於宣告基準沒有排序能力、任何模型都會贏——是灌水不是驗證。
- 下檔風險 → −1.65 × EWMA 日波動 × √5，且**允許與基準混合**
  （波動率模型當初就是靠混合才過門檻，不給同樣機會就是雙重標準）。
- 相對強弱 → 過去 20 日報酬的同日百分位（動能延續）。

### 相對強弱：日期下限把它從「通過」翻成「不通過」

修掉捏造籌碼列之前，它是這樣的：

```
樣本 165,664 列（1992 起）  排序相關 +0.0560  基準 +0.0058  差距 +0.0502  → 可新增
```

砍掉 2012 以前之後：

```
樣本  83,636 列（2012 起）  排序相關 +0.0384  基準 +0.0164  差距 +0.0220  → 不新增
     前後 20% 的實際 5 日報酬差距 −0.18%
```

**先前的「通過」完全是前 20 年那批假資料撐出來的。** 而且照它排序選前 20%，
實際報酬比後 20% 還低 0.18%——沒有任何決策價值。

第二階段（2018 起共同樣本）也一致：基礎 0.0313、＋夜盤 0.0385、＋夜盤＋期貨 0.0361，
最好的增量也不到門檻。

### 下檔風險：一個乾淨的否定

假設是「停損只會被下跌觸發，對稱波動率在偏態明顯的個股上會系統性放錯位置」。
測完的答案是：**EWMA 已經把下檔風險的排序做得跟模型一樣好**，
即使允許模型與 EWMA 混合，增量也只有 +0.0064，且有一折是負的。

## 四、成交量模型上線

```
83,636 列 / 25 檔　特徵 53 個　2012-05 ~ 2026-07
走查排序相關 0.4823　持續性基準 0.3588　差距 +0.1235　最差折 +0.1174
預測前 20% 的實際量能 1.59 倍　後 20% 0.75 倍
```

已註冊為 `volume` v1（candidate）。推論端 `Crawler/volume_model.py`
回傳 `vol_multiple` 與 `liquidity`（thin／normal／thick）。

**沒有接夜盤與期貨結構**：同一批 2018 起樣本上基礎 0.4479、＋夜盤 0.4540、
＋夜盤＋期貨 0.4463。夜盤增量 +0.0061 未達門檻 +0.01，期貨結構還讓它變差。
成交量是個股自身的量能週期，指數層級的隔夜資訊幫不上忙——這說得通。

### 它怎麼用

新增第八個角色**流動性把關**（`roles.py`）。與風險、波段、盤前定價同類：
**不投方向、只當閘門**。預測量能落在訓練期最低四分之一時否決買進。

在閒置資金裡它是**效率折扣**（thin ×0.7），刻意不動期望價差：
量能萎縮不會讓價差變小，它讓你更難用理想價格進出。把它算進成本比算進報酬誠實——
前者是確定會發生的摩擦，後者是猜測。

## 五、模型目錄：唯一的事實來源

`Crawler/model_catalog.py` 取代原本四份各說各話的清單。每個模型宣告：

```
kind        direction / gate / magnitude / reference
pages       可以出現在哪些頁面
selectable  哪些頁面可以勾選它
blocks      用到哪些資料區塊
credibility proven / weak / none / unvalidated ＋ 實測數字
```

`GET /catalog?page=voting&selectable_only=true` 是前端唯一的來源。
`ModelPicker`（投票、閒置資金）與 `ModelBar`（其餘六頁）都讀它，
前端不再自己維護模型名單。

**credibility 顯示在每個模型旁邊。** 這不是裝飾：這份資料上多數方向模型的
實測結論是「沒有 edge」，不講出來就是誤導。

### 選擇真的會改變結果

沒被選中的模型**不呼叫**——不是照跑再假裝沒看到：

```
gap,range,volatility,volume,m3_chip → 2313 / 2344 / 2327 / 6239
range,volatility                    → 6239 / 2367 / 5483 / 2449
```

投票端同理，被停用的角色照樣回傳但標記 `enabled: false`，
決策路徑會寫「已停用：籌碼分析師、消息面分析師、風險控管…」——
不回傳會讓使用者看不出自己關掉了什麼。

兩個刻意的設計：

- **持倉管家不能被關掉。** 它不依賴任何模型，只執行停損／停利／集中度紀律。
- **關掉風險控管就不給部位建議。** 部位大小完全來自波動率換算，
  給一個「預設值」比不給更危險，因為看起來像是有算過。

### LSTM 現在可以多選

`voting_engine._get_m1_signal` 原本寫死 `m02_stacked`，現在接受清單並取平均，
理由顯示成 `m02_stacked＋m09_technical＋m10_ensemble 預測價格與現價接近（變動 +0.2%）`。

多模型平均**不會**讓它變準（Iteration 11 已證十個模型的 MAE 全落在 5.17~5.25、
天真基準 5.20），但使用者有權選擇要聽誰的。

## 誠實評估

需求有四項，三項完成、一項只能部分達成：

1. ✅ 所有模型在所有分頁可見（目錄 + ModelBar/ModelPicker）
2. ✅ 資料來源統一（`panel.py`，各模型宣告需要的區塊）
3. ✅ 投票與閒置資金可選模型，且選擇真的改變結果
4. ⚠️ 「重新評估可以新增哪些模型」——評了三個，**只有一個值得新增**

第 4 項要說清楚：使用者要的大概是「多幾個模型」，但誠實的答案是這份資料上
能再擠出來的東西不多。三個候選裡兩個被否決，其中相對強弱還是在修掉一個
資料汙染之後才露出真相。與其塞三個模型進去讓畫面好看，不如只上一個真的有用的。

另外要講的是**目錄讓一件事變得無法迴避**：現在每個模型旁邊都標著可信度，
一打開投票頁就會看到 10 個 LSTM 標著「無 edge」、M3 標著「邊際」、
M2 標著「未驗證」，而標著「已驗證」的四個全都不投方向。
這是這套系統的真實狀態，先前它被四份分散的清單遮住了。

## 遺留問題

1. **M3 的 0.55 權重仍然站不住腳**（Iteration 30 遺留第 1 項未解）。
   目錄已把「2018 之後只有 51.53%」寫進 credibility，但權重沒動——
   改權重需要先做完分期驗證，那是獨立的一次迭代。
2. **`volume` v1 尚無線上台帳。** 與其他模型一樣要等預測到期才有實測數字。
3. **流動性折扣 0.7 是經驗值不是量測值。** 真正的衝擊成本要有逐筆成交資料才算得出來，
   目前沒有。這個數字寫在 `LIQUIDITY_PENALTY` 並在註解裡標明。
4. **`m2_news` 沒有 registry_type**，因此不在模型版本頁的版本管理中——
   它是規則引擎不是訓練出來的模型，但這也意味著它永遠不會累積線上紀錄。
