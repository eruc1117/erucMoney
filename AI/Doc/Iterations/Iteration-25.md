## 做了什麼

### 一、深色／淺色雙主題 + 三段字級（`dd349be`）

風格從 GitHub-dark 換成藍灰底的柔和風：卡片圓角 14px、弱陰影、行距內距放寬、
選單選中狀態加左側指示條（只靠顏色在淺色下對比不夠）、數字一律 `tabular-nums`。
主題與字級存 localStorage，寫在 `<html>` 的 data 屬性上由 CSS 變數承接；
預設字級 14px → 16px，三段 14.5 / 16 / 18。

改版真正花工夫的是讓設定「切了真的有反應」：

| 項目 | 數量 | 為什麼非改不可 |
|------|------|--------------|
| 寫死色碼 → CSS 變數 | 154 + 16 處 | 色碼寫死等於主題切換沒用 |
| 行內 px 字級 → rem | 210 處 | 字級縮放靠根字級，行內 px 不會跟著動 |
| 補定義 `--surface`、`--hover` | 2 個 | 被多處引用卻從未定義，那些樣式一直失效 |

ApexCharts 不能直接吃 CSS 變數（系列色會被拿去算漸層，`var(--blue)` 算出 NaN），
改以 `getComputedStyle` 解析成實際色值再交給圖表，色票只在 `index.css` 一份。

### 二、漲跌與損益改用台股慣例（`dcb6273`）

不是把 `--green` 的值換成紅色——那會讓程式碼「叫綠色但是紅的」。
新增語意 token：`--up`／`--down`（漲跌、損益、買賣）；`--green`／`--red` 保留給
「成功／失敗」。兩套並存是刻意的：台股 App 也是價格用紅綠、系統訊息用綠紅。

### 三、投票決策頁拆成「持有中」與「未持有」（`7190e6f`）

兩區預設排序方向相反：持有中先看「有沒有該出場的」（賣出→減碼→…），
未持有先看「有沒有該進場的」（買進→不動→…）。持有與否用**目前**持股判斷，
不用投票當下的快照。

### 四、預測比對頁重排版與修圖（`b900316`、`410aded`）

- 掃色碼成變數時漏掉跨行三元運算，留下九個 `'var(--blue)'` 餵給 ApexCharts，
  區間帶與線條本來就是壞的。
- 模型標籤亂碼：Git Bash 的 curl 以 cp950 送中文 JSON。教訓：帶中文的 payload 不要經 shell。
- 圖表改為預設顯示，摺疊只留逐日明細；用 IntersectionObserver 延後繪圖
  （**這個決定在 Iteration 26 被推翻**，見該文件）。
